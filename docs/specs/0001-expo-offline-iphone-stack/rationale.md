# 0001. Rationale

## Context

Grammy is a personal iPhone app in Polish for reading English grammar lessons. One person builds it and uses it. The scope fixes React Native, offline lessons, progress saved on the phone, and no accounts, database, server or serverless functions.

The hardest limit is the free install. A free Apple ID signs an app for about 7 days, allows 3 such apps per iPhone, and blocks several Apple features. (basis: Expo's free versus paid guide)

The project starts empty. Your Mac (checked 2026-11-27) has macOS 27.0.1 on Apple silicon, Xcode 27.2, Node 24.18.0, pnpm 12.14.0 and CocoaPods 1.17.0. Watchman is missing. Your iPhone runs iOS 27, as you reported.

Every later feature rests on this setup, so leaving it open would block the scope.

## Options considered

Plain Expo and plain React Native are compared as whole setups.

### Option 1: Expo with a local release build

Expo SDK 58, iOS project generated by Expo, release build installed from your Mac. (basis: Expo SDK 58 notes)

**Pros**:
* Little native setup, with matching library versions.
* The installed app should run without your Mac.

**Cons**:
* You follow Expo's upgrade schedule, and hand edits to `ios/` are lost.
* Offline release installs were not confirmed by the web check.

### Option 2: Plain React Native with the community command line tool

You own the Xcode project and pick each library yourself.

**Pros**:
* Full control of native code, with fewer layers.

**Cons**:
* More iOS setup and upgrade work for features this app does not need. The free signing limits stay the same.

### Option 3: Expo Go or a development build

Run through Expo Go, or through a development build connected to your Mac.

**Pros**:
* Fast feedback while coding. Expo Go needs no Apple account. (basis: Expo's free versus paid guide)

**Cons**:
* A development build normally relies on your Mac. Expo Go gives no icon of your own, and its offline use and SDK 58 support were not confirmed.

## Rationale

Option 1 fits the forces above. It needs no paid account or server, and one developer avoids most iOS upkeep. Option 2's control buys nothing for an app that shows text and tables. Option 3 puts your offline goal at risk. You can still use the simulator for quick feedback. The main risk, whether the release build works as expected, is tested first because the first build is an empty app. That matches the Tracer Bullet approach in your scope.

Choices inside the setup:

| Choice | Why | Runner up |
|---|---|---|
| Expo generates `ios/` | Nothing in this app needs hand written native code. | Keep and edit `ios/` |
| pnpm, hoisted (basis: Expo monorepo guide, search only) | Reuses your tool while avoiding isolated layout trouble. pnpm 12 was not checked with Expo. | npm |
| Expo Router (basis: `expo-router` skill) | File based screens with Expo support. | React Navigation |
| `expo-sqlite/kv-store` (basis: Expo SQLite docs) | Enough for marks and a last lesson. MMKV 4.3.2 needs an extra native library for speed you won't notice. | AsyncStorage |
| `StyleSheet` | The custom drawn look needs theme values and parts of your own anyway. | Unistyles |
| React state and context | Little shared state. | Zustand |
| TypeScript with the extra index check | Lessons are likely to be typed data with lists and tables. | `strict` only |
| Jest and Testing Library | Your Beta tag for this feature includes tests. Current versions were not checked. | Logic tests only |
| Screens and features folders | Keeps one topic's files together and gives storage one clear home. | Folders by type |
| `com.personal.grammygrammar` (my pick) | Carries no personal name. Availability was not checked. | A suffixed version |
| No over the air updates or crash service (follows the scope) | Both add a server to a one user app. | Add a crash service later |

NativeWind was also offered. The registry showed 4.2.7 as latest, and the status of version 5 was not confirmed.

## Landscape check (2026-11-27)

One limited web pass. Confirmed on fetched pages: SDK 58 (released 2026-10-15) bundles React Native 0.88 and supports Node 24.3 or newer in that line. Free installs expire after 7 days, with a 3 app limit and blocked Apple features. EAS cloud builds can't sign for a real device without the paid program. Developer Mode is required.

Not confirmed: whether a newer Expo SDK has appeared, release installs through the command line without the development server, Apple's own wording of the free limits, versions of Expo Router, Jest tools and Unistyles, AsyncStorage status, pnpm 12 with Expo, and what the React Native site currently recommends between Expo and its command line tool. The Xcode minimum (26.4, with iOS 16.4 as the lowest iOS) came from a search result only.
